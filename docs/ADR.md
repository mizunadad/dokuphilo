# 設計の記録（ADR 要点版）

> 実際の開発記録から要点だけを抜き出したもの。番号は原本と同じで、公開しないものは欠番。全文は非公開。実装は Claude（Cowork と Claude Code）で行い、判断は作者がした。

用語:
- Phase 1 … Web 版（`index.html`）。Phase 2 … OSS 公開。Phase 3 … Android 版（`app-android/`）
- S1 … Android 版の通信なしの段階（端末内の音声認識とキーワード判定）。S2 … Jev による判定を足した段階
- 「決定N」… 原本の ADR の中の決定の番号。コードのコメントから参照している

---

## ADR-002: Web 版は単一の index.html で、外部と通信しない
- 決めたこと: ビルド工程なしの `index.html` 1ファイル。判定はキーワードとテストボタン。辞典は JSON で同梱し、入力はどこにも送らず保存しない（のちに ADR-024 で、ブラウザの音声認識による処理だけを例外とした）
- 理由: 開発スピードを優先し、安全性を確かめやすい最小構成にするため

## ADR-003: Web 版ではマイクを使わない（置き換え済み → ADR-024）
- 決めたこと: 入力はテストボタンとテキスト欄だけ
- 理由: Chrome の音声認識は音声を Google のサーバーに送るため、「送らない」方針とぶつかる

## ADR-004: 安全ルール（登場賢者・免責表示・画面への出力）
- 決めたこと: 登場賢者は賢者辞典（`DokuPhilo_adv.md`）の収録者だけで、存命の人・逝去から間もない人は加えない。「※セリフは思想をもとにした創作であり、本人の発言ではありません」を常時表示する。辞典の文字列は `innerHTML` ではなく `textContent` で出す
- 理由: 本人が言っていない毒舌を名前付きで言わせるアプリであるため。XSS の経路を作らないため

## ADR-006: 登場賢者は固定の3名（置き換え済み → ADR-015）
- 決めたこと: ソクラテス・ニーチェ・サルトルから始め、データは18名に広げられる形にする
- 理由: 開発スピードを優先するため

## ADR-007: X シェアの投稿文の形式
- 決めたこと: `賢者名（創作）『パンチライン』 #DokuPhilo` とし、発話の文は絶対に入れない
- 理由: 投稿はアプリの免責表示から切り離されて広まるため、投稿文そのものに「（創作）」を入れる

## ADR-010: 煩悩は flex・bluff・anxious の3分類
- 決めたこと: flex（自己顕示）・bluff（知ったかぶり）・anxious（過剰迎合）。シチュエーションは business・romance・social
- 理由: 仕様書・モックアップ・賢者辞典がこの3分類で整理されていたため

## ADR-011: 最初は「3賢者モード」だけ
- 決めたこと: 3賢者が同時にツッコむモードだけで始め、ランダムガチャなどは後回しにする
- 理由: 開発スピードを優先するため

## ADR-012: 辞典データの形式
- 決めたこと: `index.html` に `<script type="application/json">` で埋め込み、煩悩・シチュエーション・賢者・セリフを分けて持つ（セリフは平らな配列）。どの煩悩にも当たらなければカードを出さない（B5）。別の煩悩のセリフでは代用しない（B4）
- 理由: file:// で開いても GitHub Pages でも同じように動く（別ファイルの JSON は file:// から読めない）。賢者やセリフが増えても、行を足すだけで済む

## ADR-013: パンチラインの外側の括弧は『』
- 決めたこと: 画面でもシェアでも外側は『』にする。セリフの中の引用は「」
- 理由: 中の「」と重ならず、画面とシェアで見え方がそろう

## ADR-014: 判定キーワードは誤検知を避けることを優先し、回帰テストで守る
- 決めたこと: キーワードは煩悩が表れる言い回しで、各煩悩15〜20語。普通の文にも出る語は入れない。`tools/test_keywords.mjs` で文例と期待値を確かめる
- 理由: 普通の発言に賢者がツッコむと体験が壊れ、同席者にも失礼になる。取りこぼしは直せるが、誤検知は気づきにくい

## ADR-015: 煩悩ごとの相性から3名を選ぶ（ADR-006 を置き換え）
- 決めたこと: 賢者ごとに相性のよい煩悩（`affinity`）を持ち、判定のたびに相性のある賢者から3名をランダムに選ぶ。ストア派は特定の一人の発言にしない
- 理由: 煩悩に合った賢者が出るようにするため。人数を絞り、人間が全セリフを確かめられるようにするため

## ADR-016: キーワード判定に「組み合わせ条件」を加える
- 決めたこと: きっかけの言い回しと、それを自慢に限る語が同じ文にあるときだけ当てる（例:「先生って」＋「呼ばれちゃ」。取りこぼしの例 M1・M4・M6）。文脈でしか分からない文は取りこぼしとして受け入れる。Jev の評価は当面、手元のスクリプトからのオフライン実験に限る
- 理由: 語1つでは、自慢と愚痴・呼び出しを区別できないため

## ADR-017: プラトンを加える
- 決めたこと: 相性は bluff。典拠は『国家』第5・7・10巻に絞る。「知識とは正当化された真なる信念」をプラトン本人の定義として書かない
- 理由: bluff に相性のある賢者を増やすため。その定義は『テアイテトス』で検討され、結論が出ないまま退けられたものであるため

## ADR-018: アリストテレスを加える
- 決めたこと: 相性は flex・bluff。典拠は『ニコマコス倫理学』第4巻の「真実の人」と、その過剰（大きく見せる）・不足（小さく見せる）に絞る
- 理由: 見栄と知ったかぶりの両方に、同じ箇所で素直にツッコめるため

## ADR-019: カントを加える
- 決めたこと: 相性は anxious。典拠は『啓蒙とは何か』の冒頭（自ら招いた未成年状態、「あえて賢くあれ」）に絞る。Verstand は「悟性」と訳し、「理性」と書かない
- 理由: 判断を他人に預けることへのツッコミに合うため。Vernunft（理性）と混同しないため

## ADR-020: スピノザを加える
- 決めたこと: 相性は flex。典拠は『エチカ』の高慢・名誉欲の定義と、第5部定理3に絞る。破門や孤独の経歴をネタにしない
- 理由: 自慢の正体を理解すれば受動であることをやめる、という筋が flex へのツッコミに合うため

## ADR-021: ハイデガーを加え、登場賢者は12名で打ち止めにする
- 決めたこと: 相性は bluff・anxious。典拠は『存在と時間』第27・35・38節に絞る。「空談」や「頽落」を道徳的な非難として語らせず、経歴にも触れない。賢者辞典の残り6名は見送る
- 理由: 各煩悩に相性のある賢者が7名ずつ揃ったため。残り6名は構造・対話・教育の思想で、個人の煩悩と典拠が素直に結びつかないため

## ADR-022: ライセンスは MIT だけ（コードも辞典データも）
- 決めたこと: リポジトリ全体を MIT にする。セリフが創作である旨の表記を残してほしいことは、README でお願いとして書く（法的な条件ではない）
- 理由: 辞典データが `index.html` に埋め込まれており、ライセンスを分けると説明が複雑になるため

## ADR-023: GitHub Pages の配信物を許可リストで限る
- 決めたこと: Pages は GitHub Actions で配信し、配信するファイルを名前で列挙する（`index.html` だけ）。手動実行だけにし、公式のアクションだけを使い、権限を最小にする
- 理由: ブランチをそのまま配信すると、公開する必要のない文書も配信されるため
- 補足: この公開用リポジトリには公開するファイルだけを入れているため、Pages は main ブランチから配信する

## ADR-024: Web 版に音声入力を足し、Jev のブラウザからの呼び出しは保留する（ADR-003 を置き換え）
- 決めたこと: マイクのボタンを足す（既定は OFF）。音声は確定結果だけを、4文字以上・直前と違う文のときだけ判定する（決定3）。言語は ja-JP に固定し、音声認識のないブラウザでは使えない旨を出す（決定7）。「ブラウザによっては音声が提供元のサーバーで処理される」旨のプライバシー表記と、同席者への注意を常時表示する。Jev はブラウザから呼ばない
- 理由: 実際の発話を拾いたいため。Jev の API はブラウザからの CORS が通らず（プリフライトに `Access-Control-Allow-Origin` が返らない）、利用者がキーを入れてブラウザから呼ぶ方式が成り立たないため

## ADR-025: セリフは各マスに1件以上とし、追加は分担して行う
- 決めたこと: 「賢者 × 煩悩 × シチュエーション」の各マスに1件以上置き、複数あればランダムに選ぶ。作成と典拠の確認は Cowork、採否は人間、組み込みは Claude Code。組み込みのときはセリフを書き換えず、形式の誤りなどは人間に報告する
- 理由: 同じ組み合わせで毎回同じセリフが出るのを避けるため。セリフの中身の判断を人間に残すため

## ADR-026: Android 版を OSS 公開より先に作る
- 決めたこと: Kotlin と Jetpack Compose で作る。辞典データは `index.html` から機械的に取り出し、判定関数は移植して Web 版と同じ文例・同じ期待値で確かめる（決定6）。S1（通信なし）→ S2（Jev）の2段階で進める。安全ルール: 免責と同席者への注意を常時表示し、HTML を解釈する表示を使わず、音声認識は端末内だけ（使えなければオンラインに切り替えずに止まる）、発話を保存せずログにも出さない（決定8）
- 理由: Android のネイティブアプリからの呼び出しは CORS の対象外で、Jev による文脈判定まで進めるため
- 補足: 開発では、取り出した辞典の JSON（`app-android/app/src/main/assets/dictionary.json`）をリポジトリに入れていない（決定5）。この公開用リポジトリには、clone してすぐ動くように入れている

## ADR-027: Android に Jev による判定を足す（S2）
- 決めたこと:
  - キーワードで煩悩なしの文だけを Jev に送り、煩悩ありならキーワードの結果をそのまま出す（決定1）
  - 閾値はアプリ上で変えられ、煩悩ごとに端末に残す。届かなかった値と、判定の出どころ（キーワードか Jev か）も画面に出す（決定3）
  - 送る前に名前や数字を伏せる。敬称のない人名は伏せられない（決定5）
  - キーは利用者が入力し、Android Keystore で暗号化して端末に置く。画面・ログ・リポジトリに出さず、バックアップからも除く（決定6）
  - 通信するのは Jev のクライアントだけで、送り先は1か所だけ。キーがなければ一切通信しない（決定7）
  - Jev が使えないときもキーワード判定は続け、状態を画面に出す（決定8）。キーの有無でプライバシー表記を切り替える（決定9）
- 理由: キーワードで拾える文はそのまま守り、拾えない文だけを文脈で判定するため。閾値は、ビルドし直さずに実機で動かしながら決めたいため

## ADR-028: Android の Jev の判定に bluff・anxious を足し、画面の色と配置を直す
- 決めたこと:
  - 3つの煩悩を Jev で判定し、1回の要求で送る（決定1）。定義文はオフライン実験のスクリプト（`tools/jev_defs_test.py`）の bluff_b・anxious_a を採る（決定2）。送るときのキーは煩悩の名前（決定3）
  - 閾値は全煩悩で 0.40〜0.90・0.05 刻み、既定は flex 0.80・bluff 0.55・anxious 0.55（0.55 は暫定）（決定4）。複数が届いたら値が最大のもの、同じ値なら flex → bluff → anxious の順（決定5）
  - マイクのボタンを下の固定バーに置く（決定7）。下の固定バーには判定の行（3煩悩の値。キーワードで当たったものは「KW」）と応答時間も出す。スクロールの中の並びを整理し（決定8）、Jev の誤りは先頭に出す（決定10）。タグは1行にまとめ（決定11）、新しい判定が出たら先頭へスクロールする（決定13）
  - 煩悩ごとに固定の色を付け（flex 赤紫・bluff 黄橙・anxious 水色）、Jev は塗り・キーワードは枠で分ける。色だけに頼らず文字も出す（決定14〜16）
- 理由: オフライン実験（定義6件 × 38文）で、この2つの定義文が期待ありの文となしの文をいちばん分けた。既定 0.80 では bluff・anxious が7文中2文しか届かなかった。画面は色がなく、判定の種類も出どころも文字を読まないと分からず、操作のたびにスクロールが要ったため
- 限界: 実験の文は定義文と同じ作者の作文で、結果は甘く出ている
